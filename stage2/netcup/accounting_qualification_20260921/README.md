This is technical verification evidence, not the assignment report or a spending
report. At qualification, the baseline service is stopped with 119 of 178 final
results retained. No new paid model calls were made for this correction.

## Correction and preserved limits

The earlier ledger reduced a settled response to its known charge while its
independent receipt was still pending. The remaining worst-case liability was
only restored when the completed trial registered a deferral. This could cross
a stage ceiling after dispatch. Pending receipt bounds now remain in hard
stage, project and account exposure throughout the active trial. The separately
approved estimated per-trial allowance is unchanged.

An explicit, private activation batch can reduce only the extra hold for an
exact receipt matching its original settled response, generation, provider,
charge and native token counts. Staging alone has no effect. Every use checks
original deferral and activation hashes. Original SQLite rows, request files,
results and registries remain immutable. Unknown requests remain reserved;
billing-incomplete trials are not relabelled as financially verified.

In an isolated native copy, 13 recovered receipts reduced final-stage exposure
from US$6.16396148 to US$4.78396452, releasing US$1.37999696 of conservative
holds, **not a refund**. Development exposure stayed US$0.91324768. No cap,
reserve, model, provider, task, output allowance or deadline was changed.

## Reproduction and deployment boundary

Use a credential-free copy under the native host's `.runtime`, preserving original
dataset/configuration metadata and private evidence permissions. Run the complete
suite, copied-evidence rehearsal and gateway checks with
`netcup/qualify_receipt_accounting.py`; its write modes refuse the production
root. Qualify the replacement with `scored_runtime_probe.py --harness custom
--gateway-image-id <immutable-image-id>` and then register the candidate transition.

`netcup/deploy_receipt_accounting.py` separately requires a stopped service,
all three ownership locks, unchanged original sources and matching copied evidence.
It archives the original runtime/sources, installs only eight allowlisted source
files plus additive proof/activation records, and verifies through a fresh process
importing the deployed code. It does not start scoring. Back up its archive
off-server and verify the hashes before separately resuming the existing runner.

The first 119 results are not rerun or silently attributed to the corrected
runtime. Report this accounting-only execution amendment in final provenance;
do not infer a runtime-efficiency victory across versions, especially while
financial evidence is incomplete. Remaining task costs and the custom-harness
outcome are not guaranteed by these software tests.
