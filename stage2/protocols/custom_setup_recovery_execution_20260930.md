# Separate recovery execution integration

This continues the approved fixed three-cell plan. It does not change the
original 89 outcomes, denominator, model, prompts, tools, resources or official
deadlines. The original preparation function and shared lifecycle and trace
sources remain unchanged. No original key is reused. Recovery remains a
separate denominator of three with one fresh attempt per cell, in original
order. A missing result or incomplete diagnostic cannot authorise replay.

## Current boundary

The recovery-only scored scope, durable observation, image builder, isolated
fake provider, six-case host producer, qualification reader/producer, sequential

completed audit/archive/export are local implementation.

The complete candidate must pass its final source-bound local checks and be
committed before exclusive installation. Actual native regressions and all six
real isolated cases must then pass before any paid launch. The original archived
reporter and retained archive are immutable. No earlier matched-repeat route is
generalised here.

## Durable setup evidence and scoped execution

`scored_trial.run_trial` accepts only an explicit recovery experiment or a
synthetic recovery permit, never both or a mixed historical/custom/baseline
route. The real live locked session and freshly reread qualification issue
the original C0-NC factory themselves. Each registered fresh cell must be the
next exact key. Construction, callback and permit lifetime are single-use and
bound to the owning process, main thread and async task. The setup callback
runs in the shared lifecycle's own setup task, while result finalisation stays
in the owning scored task after that setup task settles.

The callback invokes the unchanged preparation exactly once. Its allowlisted
observation is retained with the actual result in the existing finally writer,
including nonzero, exception and cancellation outcomes. Diagnostic capture
failure retains available metadata and explicit incompleteness; it does not
replace the original exception, manufacture success or justify another
attempt. The shared lifecycle's all-null AgentContext is not evidence that an
agent ran. Failed preparation must have no agent/model/verifier execution.
No arbitrary output, exception messages, stacks or task/model payloads enter
the observation. The 900-second setup and 180-second preparation command,
zero automatic preparation retries and original package behaviour remain.

Protected evidence is private, canonical, owned and single-link, with ACL,
raw-byte and file-identity checks. Same-byte replacement is a failure. Writes
are exclusive and durable. Existing or partial operation state is terminal,
not an automatic resume path. Accounting retains zero, missing rewards and
unknown costs without a financial, request, retry or score gate.

## Detached trusted operations

The pinned connection now has three fixed operations: prerequisite inspection,
qualification and recovery dispatch. There is no arbitrary executable, root,
callback, native signal, stop, restart or retry parameter. Each operation has
its own exclusive operator/native state directory and detached systemd unit.
The original SSH identity, destination and host-key options are preserved.
The complete committed original/current union is read before project imports,
including the actual fixed operation consumer. Credential/environment/import
effect refusals remain latched.

Every operation still performs the real fresh original completed audit and
authenticates the same retained off-server archive before all ancestor locks.
Inspection success is written only after normal session exit. Qualification
and dispatch instead return a durable committed-handoff acknowledgement while
the service owns the live session. That acknowledgement explicitly means
accepted, not qualified, admitted, completed or scored. The service continues
independently of Mac sleep or acknowledgement loss and awaits the actual fixed
consumer in the same main-thread task. Actual producer bytes are bound, the
normal session exit recheck invalidates both handles, and only then can the
service write durable operation completion. No service runtime ceiling is
introduced. Transport windows are not benchmark deadlines.

Execution units retain successful exit metadata with RemainAfterExit=yes; no
benchmark process remains after completion. Paid admission rereads the actual
qualification unit invocation, successful main-process exit, immutable producer
bytes and file identities. Not-found/default exit metadata is insufficient.
Read-only status uses the same committed bootstrap and fixed pinned route but
opens no session, reads no archive and grants no admission. A late relay failure
after a complete handoff is retained as transport uncertainty, not permission
to repeat or cancel native work. Later documentation-only commits may verify an
earlier operation only with identical bound bytes and its actual original
operation revision; service startup still requires exact live handoff equality.

The dispatcher registers exactly three and runs them sequentially, retaining
actual saved results rather than trusting coroutine returns. Clean failed
outcomes may advance to the next fresh key; partial, inconsistent or incomplete
evidence cannot. Shared Retry-After is observed before the next official task
clock. Original results stay separate. Completed dispatch metadata is not the
separate completed audit or verified off-server backup.

## Exclusive installation and completed reporting

The installer first requires actual new-root absence, protected original/current
inputs, no overlapping required native work and the complete existing ancestor
lock chain. It installs only the new private recovery root, precreates its three
locks, and copies the actual protected Python environment, dataset and tokenizer
bytes. Credentials move only between fixed private native paths. Original roots
are never patched. Every existing or partial destination is terminal; no reuse,
chmod repair, deletion or automatic retry exists.
