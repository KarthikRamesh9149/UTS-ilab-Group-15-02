# Older-parent no-cutoff revision

## Scope

The direct-final decision permits one separately labelled revision if the best
audited C0/C1/C2/C3 whole candidate still has the old execution cutoffs. This
module was prepared for that case. The subsequent completed four-block audit
selected C0: 15/20, versus C1 14/20, C2 14/20 and C3 13/20. All 80 original
outcomes are preserved in a freshly verified evidence freeze. This does not
register a revised trial or grant paid admission.

`no_cutoff_custom_agent.py` assembles version `stage2-candidate-0.5.0`. Its
identity is the original whole parent plus `-NC`: `C0-NC`, `C1-NC` or `C2-NC`.
For C2 the original C0/C1 parent is retained as additional lineage. Exercising
all parent shapes in synthetic tests is not permission to run three paid
revisions; the actual parent must come from the completed four-block audit.
That parent is now C0, so the only intended paid revision is C0-NC.

This is not the original parent's measured score and is not C3 under another
name. The revision retains the parent's planning and completion-check choices,
while removing the specifically identified execution cutoffs. It does not add
C3's dynamic remaining-time advice. The only prompt amendment describes the
changed command and completion contract truthfully.

## Execution

The adapter reuses unchanged deadline-governed command, job and completion
components from the reviewed C3 implementation. The shared original files
remain unchanged. A separate runner constructor omits only C3's advisory time
middleware while retaining the filesystem tool's official-time allowance.

- Commands default to the time left on the existing official task clock.
  An explicit shorter timeout remains an agent choice. The library's separate
  one-hour command ceiling is replaced by the official allowance.
- Background handles have no active or lifetime count quota. Processes still
  share the task's official CPU and memory.
- Incomplete completion messages can be repaired while official time remains.
  C2 still requires its declared observed checks; invalid completion does not
  become a pass.
- The graph has no artificial model-call ceiling. Provider routing, actual
  credit/authentication/identity checks and shared retries stay unchanged.
- The task clock is neither reset after setup nor renewed between tool calls.
  Cancellation, container-only execution, private logging, model revocation,
  deferred service cleanup and no replay remain required.

No financial cap or reserve is introduced. Actual provider/context limits and
finite tool-output/transfer windows remain. These are not claims of literally
unlimited operation or a performance improvement.

## Capture transport correction

The C3 audit retained a capture-helper exit 143 after about 75 seconds of a
3,600-second allowance. A structural check of private development evidence
found full-command process matching in the last execute call. No raw command
or task answer was exported, and the original attempt was not replayed.

The existing helper carries literal command text in its own process arguments.
A separate, harmless local fixture reproduced the general collision: its child
examined only its own capture parent's arguments and sent SIGTERM only to that
owned PID when a unique marker matched. This establishes the mechanism, not
the exact original causal sequence.

`no_cutoff_capture_backend.py` encodes the helper source in its arguments. The
decoded capture implementation is unchanged, and the same fixture completes
without matching the helper. Genuine helper termination, invalid responses,
command exit codes and official deadlines remain visible; no command is
automatically retried. The original C3 files and result are unchanged.

Encoding is not encryption and does not prevent deliberately broad termination
inside the task container. It expands the RPC argument payload; existing finite
transport limits still apply. Native qualification must cover the actual
encoded path, structured reads and sizeable commands as well as process
matching. This is an additional explicit runtime correction, not a claim that
only command cutoffs changed or that the revision inherits C0's score.

the separate current host. It refuses an existing completed qualification,
