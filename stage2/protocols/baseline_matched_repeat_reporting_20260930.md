# Separate baseline-repeat completion and reporting

These controls are prospective local implementation. No baseline root, native
qualification, service, paid attempt, completed audit, archive or public result
is implied. The fixed order remains one new89 Terminus-2, its actual audit and
ONE verified backup, then one new89 OpenHands. Recovery's actual three outcomes,
completed audit, ONE separate verified backup and export remain prerequisites.
Original52/89 and44/89 and all custom/recovery outcomes stay separate. No
extra variants, best-of score, replay, parallel dispatch or new resource/cost/
model/request/retry limit is introduced. Unknown cost remains unknown.

## Completed service and actual89 reads

The new completion reader requires the actual retained manager invocation,
successful exited one-shot unit, PID/start-tick absence, protected intent,
accepted handoff, terminal/log hashes and exact durable operation inventory.
It rereads sources and private bytes/identities after its last manager check.
A saved result, accepted handoff or unloaded unit's default fields is not proof
that the actual service ended. A transport-only marker is retained, never
treated as authority to repeat the operation.

The completed report requires the real same-task live locked session and
actual qualification and paid-service completion. It reads all89 start/result,
phase/trace, original deadline and passive-accounting records with exact
registered task/image/official-limit identity, revocation and cleanup. Zero,
unknown cost and genuinely missing verifier results remain distinct. Full89,
fixed development20 and remaining69 have separate aggregate denominators;
measured and proven-unexecuted durations are never combined into fake totals.
Final native observations precede actual source/evidence/inventory/absence
rereads. No returned coroutine flag or saved self-consistent JSON is admission.

The separate baseline phase reader preserves the archived phase algorithm.
An AST-parity regression permits only the explicit Terminus/OpenHands identity
guard and trace-harness comparison/message change. The archived custom reader
is not modified or made to masquerade as a baseline.

## ONE private archive and allowlisted projection

The new archive inventory binds every required file, actual empty directory,
size/hash and corroborated absence. Extra registered agent/verifier payloads
use the explicitly observed protected-log compatibility behind owned0700
trial boundaries; required evidence remains private. Source permissions are
never changed. Credential/cache entries remain excluded and raw payload is
hashed, never returned or interpreted as task solutions/model exchanges.

The producer streams tar/gzip bytes without a native archive pathname. The
strict existing-byte reader checks every member, all source/qualification/
registration/runtime anchors, exact inventories, genuine absences, gzip and
tar endings, unsafe/duplicate/linked/special entries and compressed checksum.
The framed-stream reader consumes only its declared archive bytes, leaving
peer identity and final authenticated commitment to the trusted caller. The
path reader also requires private regular single-link canonical files with
unchanged identities. No extraction, archive recreation, historical installed-
byte attestation, full restore or paid admission is claimed.

The pure public projection returns only summary.json, trials.json and trials.csv
bytes. It validates the allowlisted report and archive-verification schema,
retains all89 rows, original scores, subset denominators and disclosed inherited
million-turn baseline guards. Missing numeric values remain JSON null/empty
CSV cells. The function is not an exporter or proof that a native audit ran:
the actual future writer must freshly audit and reread the SAME verified
private archive before one exclusive durable publication.

## Source-bound startup controls

The new stdlib bootstrap derives the complete current inventory from the
actual pinned original/final private qualifications and bound policy AST before
project imports. It requires its fixed root, own isolated interpreter, exact
credential-free environment and absent bytecode path. Protection helpers are
AST-identical to the recovery versions: full canonical ownership/group/ACL,
single-link, private mode, byte and file-identity checks remain. Import writes,
network and process creation are denied; caught socket capability probes are
refused before construction. Credential reads and environment mutation remain
forbidden afterward, with latched violations. This is defence in depth, not
an OS sandbox.

Its recovery preflight reads the actual frozen r6 source union and invokes the
real source-bound r6 status reader in r6's own interpreter. All three retained
outcomes and successful service exit are required without a score floor.
This preflight is NOT a fresh recovery audit, archive verification or live
successor witness; those remain separate trusted integration requirements.

The source-bound ordered-stream adapter waits for one actual post-audit byte
before the archived baseline reader checks ancestor processes. It returns
that byte exactly once, preserves every subsequent header/archive/commit/EOF
byte and actual descriptor identity, and grants no admission. The actual
future service must place this barrier before opening its live session.
No archived sender, reporter or handoff source is edited.

The recovery-specific operator component has no saved-audit input. Its fixed
isolated Mac child checks committed baseline/recovery sources before imports,
then calls the real frozen recovery reporting audit, including that route's
fresh original audit and SAME original archive authentication. It checks the
returned audit against the retained completed recovery snapshot, strictly
reads the SAME recovery archive and requires deterministic already-committed
public results plus exact private backup/export inventories. Final source,
archive, public/private bytes and identities are reread. The child is separate
because new baseline imports must not enter the frozen recovery reader's
loaded-source inventory. The exact Mac environment includes its observed
CoreFoundation user-text-encoding variable; unexpected variables still refuse.
No audit was invoked natively by the local tests of this component.

The separate recovery stream verifier retains the frozen recovery path
verifier's strict inventory, member, source/qualification, raw-byte, true-
